决策边界三档（Agent 管理的硬约束）

关键不是智能体数量，而是都在清晰的治理边界内协作。安全不能只写在提示词里，访问与执行必须过实际身份认证与运行时授权。

可自动执行

  • 资产发现与目录更新
  • 质量稽核与异常打点
  • 日志、审计、评测数据采集
  • 影响面初筛、回归队列入队

需人工复核

  • 语义映射与术语候选
  • 分类分级建议
  • 异常交易标记
  • 知识切片与证据候选

需授权批准

  • 字段 / 主数据合并
  • 口径与本体版本发布
  • 访问范围扩大、训练授权
  • 风险定性与对外输出
不能为提高回答率自行放宽口径或扩大访问权限。高影响任务建立人工复核、回退机制与明确责任归属。

Agent-ready 服务目录（8 个）

服务管理不是把数据接口对外开放，而是把治理后的数据与语义变成智能体可调用、可约束、可验证的业务能力。点服务看契约：输入 / 输出 / 四种权限 / 证据回传要求。

契约强制项：任何返回给 Agent 的结论必须附 资产版本 + 规则编号 + 术语版本 + 任务日志号；未就绪资产显式标注缺口，不静默填空。
四种权限必须分离：允许系统访问 / 允许模型检索 / 允许用于训练 / 允许对外输出。

四层协同：服务落在哪一层

L1
制度与责任定边界：谁有权定义、谁承担责任、什么行为被允许
L2
数据治理平台把要求变成可执行规则、接口与控制机制（服务目录在此）
L3
治理智能体发现、检查、建议、分析、测试、监测、报告
L4
业务智能体检索、规划、决策辅助、工具调用、任务执行
业务结果与反馈闭环：以真实任务结果验证数据与语义质量，驱动治理规则持续改进。

四层协同 + 反馈闭环

制度与责任 → 平台 → 治理智能体 → 业务智能体
→ 业务结果与反馈闭环 → 反哺治理规则
三条原则：先场景、后平台；先责任、后自动化；先建立可信闭环、再扩大治理范围。
责任不清，自动化只是更快地产生错误；语义没确认，本体可能成为新的知识孤岛；没有应用评测，功能再丰富也无法证明价值。
